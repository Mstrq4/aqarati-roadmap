# ملحق معتمد: التطبيق الأصلي React Native ومعجم المصطلحات

التاريخ: 2026-08-31
الحالة: معتمد من صاحب المشروع.

## تصحيح معماري أساسي

- تطبيق الهاتف في مشروع «عقاراتي» **تطبيق فعلي مبني بـ React Native** لأندرويد وiOS، وليس PWA.
- الويب يبقى منصة SaaS للإدارة والعرض العام للعميل، ولا يوصف كتطبيق الهاتف.
- كل موضع في الخطة الحالية يستخدم `PWA` بمعنى تطبيق الهاتف يجب تصحيحه إلى `React Native` أو صياغة عربية واضحة مثل «تطبيق الهاتف الأصلي».
- React Native يستخدم مكونات تُرسم إلى واجهات المنصة الأصلية، لذلك تظهر الخطة مسار تطبيق الهاتف كمسار مستقل داخل التنفيذ، لا كتوسعة للويب.

### تطبيق React Native

يظهر في الخطة بمهمات واضحة تشمل:
- تهيئة مشروع React Native وبنية التطبيق.
- التنقل بين الشاشات وربط المسارات الداخلية Deep Linking.
- المصادقة وربط جلسة المستخدم مع Supabase.
- شاشات العقارات والباحثين والقروبات والاشتراكات.
- Push Notifications للتنبيهات.
- اختبار فعلي على Android وiOS.
- تجهيز نسخ Release Candidate وتسليم متطلبات النشر.

## شرح المصطلحات داخل الواجهة

لا يعتمد النظام على أن يعرف العميل المصطلحات التقنية مسبقًا.

- كل مصطلح تقني معروف يظهر بجانبه زر معلومات `Info` صغير.
- على سطح المكتب: focus/hover يعطي وصفًا مختصرًا، والنقر يفتح شرحًا ثابتًا قابلًا للقراءة.
- على الجوال: النقر يفتح Popover/Dialog؛ لا نعتمد على hover.
- الشرح الأساسي يكون عربيًا بسيطًا، ثم الاسم التقني بين قوسين عند الحاجة.
- توجد لوحة «معجم المصطلحات» داخل صفحة الخطة الزمنية يمكن فتحها لرؤية جميع المصطلحات دفعة واحدة.
- زر المعلومات نفسه قابل للوصول من لوحة المفاتيح وله `aria-label` واضح.

### المصطلحات الأساسية

- React Native: إطار لبناء تطبيقات Android وiOS باستخدام React مع واجهات أصلية للمنصة.
- SaaS: منصة برمجية تُستخدم عبر الإنترنت وتُدار مركزيًا.
- RTL: اتجاه واجهة من اليمين إلى اليسار للعربية.
- Onboarding: خطوات التهيئة الأولى التي تعرّف المستخدم بالمنتج وتساعده على البدء.
- Supabase: منصة الخلفية المستخدمة لقاعدة البيانات والمصادقة والتحديث اللحظي.
- RLS: سياسات على مستوى صفوف قاعدة البيانات تحدد من يستطيع قراءة أو تعديل كل سجل.
- Realtime: وصول التغييرات إلى الشاشات المفتوحة دون تحديث الصفحة يدويًا.
- CRUD: إنشاء السجلات وقراءتها وتعديلها وحذفها.
- Deep Linking: فتح شاشة محددة داخل تطبيق الهاتف من رابط مباشر.
- Push Notifications: إشعارات تصل إلى الهاتف حتى عندما لا تكون الشاشة مفتوحة.
- Saved Search: حفظ شروط بحث المستخدم لإعادة استخدامها وإرسال تنبيهات عند ظهور نتائج مناسبة.
- AI Matching: حساب توافق الباحث مع العقار وفق متطلباته وخصائص العقار.
- AI Rerank: إعادة ترتيب نتائج المطابقة بالذكاء الاصطناعي لإبراز الأنسب.
- Alpha: نسخة مبكرة لاختبار الوظائف الأساسية داخليًا.
- Beta: نسخة أوسع للاختبار قبل النسخة النهائية.
- Release Candidate: نسخة مرشحة للإطلاق لا ينقصها إلا اجتياز الاختبارات والقبول.
- E2E: اختبار رحلة كاملة من بداية الإجراء حتى نهايته عبر مكونات النظام.
- Add-ons: إضافات مدفوعة أو حصص إضافية دون تغيير الباقة الأساسية.
- Upgrade Nudge: تنبيه غير مزعج يقترح الترقية عندما يصل المستخدم إلى حد الباقة.

## منطق تقدم المهمة

- مخططة: 0%.
- قيد التنفيذ: 0–79%، ويُعدّل تدريجيًا دون قفزة ثابتة.
- مراجعة: 80%.
- مكتملة: 100%.
- متوقفة/مؤجلة: تحتفظ بآخر نسبة وصلت إليها.

يُفرض نفس المنطق في الواجهة وقاعدة البيانات حتى لا تختلف النتيجة بين الأجهزة.

## مرجع التصميم

- لوحة الإدارة: Data-Dense / Bento، بطاقات مدمجة، 4 KPIs في الصف الواسع، تباين واضح، حركة 150–300ms.
- الشرح التقني يستخدم progressive disclosure: النص العربي البسيط ظاهر، والتفاصيل الفنية خلف زر المعلومات.
- لا تمرير أفقي إجباري في الخطة الزمنية على الهاتف؛ تتحول إلى بطاقات ومسارات رأسية قابلة للمسح البصري.
